CSS & Design System

The design tokens and component patterns that keep every page visually consistent.

One shared token file

Design tokens — colors, fonts, the fluid type scale, easing curves, and layout primitives — are declared once in assets/css/tokens.css and linked from every page, instead of being redeclared per page. This file also centralizes the shared @font-face and base CSS reset.

Color tokens

TokenValueUsed for
--black#07090BPage background
--panel#0A0F13Cards, code blocks, callouts
--line / --line-lit#1B2328 / #2A353CBorders (resting / hover)

--text#D3DBDDBody text
--white#F2F5F5Headings, emphasis
--accent / --accent-dim#8FB8C4 / #46626BLinks, active states, highlights

Typography

  • --font-logo — 'NKX Display', used for the wordmark.
  • --font-b — Outfit, the primary body/UI typeface.
  • --font-m — Space Mono, used for labels, eyebrows, and code.
  • A fluid type scale (--fs-*) built with clamp(), so heading sizes respond to viewport width without separate breakpoint overrides for font-size alone.

Why this is centralized but per-page overrides still work

Because tokens.css is linked before each page's own <style> block, a page can still override any token locally (the cascade favors the later declaration) — a few pages intentionally do this for a slightly different accent color. This means the shared file could be introduced without changing how any existing page renders.

Info
This is exactly how the token file was introduced to the codebase: only variables with byte-identical values across pages were removed from each page's local CSS, so nothing visually changed — see Changelog.

Component styles

Reusable component patterns — cards, callouts, code blocks with copy buttons, badges — are defined in feature-scoped stylesheets rather than the token file itself. This documentation system's own components live in assets/docs/docs.css.
