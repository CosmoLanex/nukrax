Architecture

API & Integrations

How NUKRAX's backend services fit together today — and what's planned for external integrations.

How NUKRAX's backend is composed today

NUKRAX doesn't (yet) expose a public API for third-party integrations. Internally, the platform is composed of a few managed services rather than a single monolithic backend:

ServiceUsed for
SupabaseAuthentication, the Postgres database (profiles, posts, follows, notifications), and Realtime for the Community feed.
Cloudflare WorkersServing the site itself, and proxying AI assistant requests.
ResendTransactional email (confirmation, magic links) via Cloudflare DNS.

Authentication

Email/password, GitHub OAuth, and magic links are all handled through Supabase Auth. Row-Level Security (RLS) policies on the database enforce that users can only read/write data they're permitted to — there's no separate authorization layer to configure.

AI assistant proxy

The AI assistant ("Lanux") calls a Cloudflare Worker endpoint rather than talking to an upstream AI provider directly from the browser — this keeps the provider API key server-side, stored as a Worker secret rather than in client code. If that network call isn't available, a local, offline knowledge-base responder answers common questions instead.

Keeping the free-tier database warm

A scheduled GitHub Actions workflow pings the Supabase project periodically to prevent the free-tier database from pausing due to inactivity.

Planned: public API

Planned
A public, authenticated API for reading account and trade performance data programmatically is on the roadmap. Nothing here today should be treated as a stable integration surface — there is no versioned public endpoint yet.

Planned: trade event webhooks

Planned
Webhook notifications for trade events (opened, closed, risk-limit hit) are being explored for a future release, potentially to support the terminal dashboard and third-party alerting. Not available today.
