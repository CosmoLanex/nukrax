How the site is organized

NUKRAX is a static site — plain HTML, CSS, and JavaScript, served through a Cloudflare Worker with an assets binding. There's no build step: what you edit is what ships.

The assets/data/ architecture

Shared, non-visual JavaScript — breakpoints, device detection, responsive math, layout constants, site metadata, and small utilities — lives in assets/data/ and is re-exported from a single entry point, assets/data/data.js. Every page links this module so new code always has one place to pull shared configuration from instead of re-implementing it per page. See Responsive Design and JavaScript Architecture for the full breakdown.

Feature-scoped asset folders

Beyond the shared data/ and css/ folders, most interactive features get their own folder colocating their CSS and JS — assets/cube/, assets/auth/, assets/ai/, assets/community/, and assets/docs/ (this documentation system) all follow the same pattern: a self-contained feature with its own stylesheet and script.

Why there's no build step

Info
The site is deployed as-is through Cloudflare Workers — no bundler, no transpilation, no CSS preprocessor. This keeps deploys simple and instant, but it does mean shared CSS breakpoints can't be generated from a single source the way a build tool would allow. See Responsive Design for how this is handled.
