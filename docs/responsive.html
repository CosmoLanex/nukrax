Responsive Design

The breakpoint scale, device detection, and fluid-sizing helpers that keep every page working across screen sizes.

A centralized responsive architecture

NUKRAX is built without a bundler or CSS preprocessor, so "centralizing" responsive logic means two related but distinct things: a shared set of design tokens for CSS, and a shared JS module for anything that needs to branch on screen size, device type, or viewport in script.

The canonical breakpoint scale

Defined once in assets/data/breakpoints.js, matching the values already in real use across the site's CSS rather than an arbitrary industry-standard scale:

NameWidthRoughly
sm480pxLarge phones
md640pxSmall tablets / large phones landscape
ml760pxMost common page breakpoint
lg860pxSmall tablets
tab900pxTablets
tl1000pxLarge tablets / small laptops
xl1100pxSmall laptops
xxl1440pxLarge desktop

Why CSS breakpoints aren't driven by variables

Info
CSS media-query features (the part inside @media (max-width: …)) can't read custom properties in any browser — only literal lengths are allowed there. Without a build step to generate one from the other, the breakpoint scale is kept in sync by hand between breakpoints.js and each page's CSS, rather than the CSS reading from the JS.

Device detection

assets/data/device.js centralizes the checks that used to be re-implemented per script — device class, touch vs. pointer input, reduced motion, and viewport size:

JAVASCRIPT 
import { getDeviceClass, prefersReducedMotion, isTouchDevice } from "../assets/data/data.js";

getDeviceClass();        // "mobile" | "tablet" | "laptop" | "desktop"
prefersReducedMotion();  // true/false — honored by the reveal + hero animations
isTouchDevice();         // true when there's no fine hover-capable pointer

Fluid sizing in JS

assets/data/responsive.js mirrors the CSS clamp() type scale for anything computed in script — canvas drawing, dynamic element sizing — so JS-driven and CSS-driven sizing stay on the same curve:

JAVASCRIPT 
import { fluidSize, scaleByViewport } from "../assets/data/data.js";

fluidSize(16, 2, 24);   // same as CSS clamp(16px, 2vw, 24px)
scaleByViewport(count, { minWidth: 480, maxWidth: 1440, minValue: 40, maxValue: 160 });

What's been tested

The layout has been checked across small phones, large phones, foldables, tablets, small laptops, standard laptops, desktop monitors, and ultrawide displays — with a focus on no overflow, no overlapping elements, and no inaccessible controls at any width.
