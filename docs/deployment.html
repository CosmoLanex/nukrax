Deployment

How NUKRAX ships — hosting, DNS, and the no-build-step deployment model.

How the site ships

NUKRAX deploys as a static site through Cloudflare Workers, using an assets binding — there's no build step between committing a change and it being deployable. Deployment is managed independently via GitHub and Cloudflare Workers.

Hosting

PieceProvider
Static assets & routingCloudflare Workers (assets binding)
DNS & email sendingCloudflare DNS + Resend
Database, auth, realtimeSupabase

Why there's no build step

Every HTML, CSS, and JS file in the repository is exactly what gets served — no bundler, transpiler, or CSS preprocessor sits in between. This keeps deploys fast and the failure surface small, at the cost of a few things a build tool would normally provide for free (see Responsive Design for how breakpoints are handled without one).

Scheduled keep-alive

A GitHub Actions workflow runs on a schedule to keep the Supabase free-tier database from pausing due to inactivity — a small operational safeguard rather than a deployment step itself.

Environments

Info
There is a single production environment today. A staging/preview environment for testing changes before they reach nukrax.com is not currently part of the deployment process.

Planned: CI checks on deploy

Planned
Automated checks (broken-link detection, HTML/CSS validation) running on every push are being considered, building on the same validation approach used to QA this documentation system before release.
