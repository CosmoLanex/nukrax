Architecture

Accessibility

What's implemented for accessibility today, and what's explicitly still on the roadmap.

What's supported today

Accessibility is treated as an ongoing practice rather than a finished checklist — this page documents what's actually implemented today, and what's intentionally still on the roadmap.

Reduced motion

Every animated pattern — reveal-on-scroll, the hero cube, particle canvases — checks prefers-reduced-motion and either skips the animation entirely or reduces it to an instant state change.

Keyboard & focus

  • Interactive elements use real <a> and <button> elements rather than clickable <div>s, so keyboard focus and Enter/Space activation work by default.
  • The mobile documentation drawer traps Escape-to-close and is dismissible by clicking its backdrop.
  • Toggle buttons (like the docs mobile menu) expose aria-expanded.

Semantic structure

Pages use landmark elements (<nav>, <main>, <aside>) and a single <h1> per page, with breadcrumbs marked via aria-label="Breadcrumb" and the current page marked with aria-current="page".

Color & contrast

The dark palette (CSS & Design System) was chosen with body text (--text on --black) at a comfortably high contrast ratio; muted text is reserved for secondary/supporting content rather than primary reading content.

Known gaps

Warning
A full audit against WCAG 2.1 AA (systematic alt-text review, complete focus-order testing, and screen-reader pass on the trading terminal's data-heavy views) hasn't been completed yet. Treat this page as a snapshot of what's known to work rather than a compliance guarantee.

Planned improvements

Planned
A dedicated skip-to-content link on every page, and a full screen-reader pass on the live trading terminal, are planned but not yet implemented.
