Layout System

The shared layout primitives — container, gutter, spacing, and z-index scales — used across every page.

Layout primitives

Every page shares the same layout primitives, defined once as CSS custom properties in assets/css/tokens.css and mirrored on the JS side in assets/data/layout.js for anything that needs to compute layout in code (canvas sizing, dynamic spacing, etc).

Container & gutter

TokenValueUsed for
--container1180pxMax content width for page sections.
--gutterclamp(24px, 5vw, 64px)Fluid horizontal page padding.

Spacing scale

The JS-side spacing scale (SPACING in assets/data/layout.js) mirrors the visual rhythm used throughout the CSS, for anything computing layout in script rather than pure CSS:

JAVASCRIPT 
import { SPACING } from "../assets/data/data.js";

SPACING.xxs   // 4
SPACING.xs    // 8
SPACING.sm    // 12
SPACING.md    // 16
SPACING.lg    // 24
SPACING.xl    // 32
SPACING.xxl   // 48
SPACING.xxxl  // 64

Z-index scale

A shared z-index scale keeps stacking contexts predictable as new overlays get added — sticky nav, modals, toasts, and tooltips all have a defined layer instead of ad hoc numbers:

JAVASCRIPT 
import { Z_INDEX } from "../assets/data/data.js";

Z_INDEX.stickyNav    // 100
Z_INDEX.overlay      // 500
Z_INDEX.modal        // 900
Z_INDEX.toast        // 950

Common grid patterns

Card grids across the site (feature highlights, EA comparison cards, documentation cards) use the same auto-fit pattern:

CSS 
display: grid;
grid-template-columns: repeat(auto-fit, minmax(200px, 1fr));
gap: 14px;

This documentation's own layout

The docs system itself follows the same primitives: a fixed-width sidebar, a reading-width main column (max 760px for comfortable line length), and a right-hand table of contents — collapsing to a single column with a slide-out drawer below 860px. See Responsive Design for the breakpoint system behind that.
